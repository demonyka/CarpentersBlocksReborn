# Carpenter's Blocks (переписанный)

Новая реализация мода [Carpenter's Blocks](https://github.com/Mineshopper/carpentersblocks).
Поведение берём из версии 1.7.10, код пишем заново. Лицензия LGPL-2.1, как у оригинала.

## Платформы

| Minecraft | Загрузчик | Статус |
|---|---|---|
| 1.16.5 | Forge 36.2+ | в работе |
| 1.16.5 | Fabric (Loader 0.14+, Fabric API) | в работе |
| 1.12.2 | Forge | позже, на том же `core` |

## Состав мода

Всё из 1.7.10, кроме **сейфа, кровати, цветочного горшка, плитки, стамески с узорами и оверлеев**.

| Группа | Блоки | Статус |
|---|---|---|
| Основа | Плотницкий блок, молоток | ✅ логика и отрисовка покрытий, боковых покрытий, красок |
| — | Стамеска с узорами, оверлеи | не делаем (решение владельца) |
| Основа | Склоны: 65 форм, 5 видов, установка, автосоединение, молоток, смена вида колёсиком, покрытия, коллизия, дроп | ✅ |
| Основа | Лестницы (28 форм, автосоединение), складной блок (4 угла, автоскат) | ✅ |
| Ограждения и проёмы | Барьер, калитка, люк, дверь (двойные), гаражная дверь | ✅ |
| Редстоун | Кнопка, рычаг, нажимная плита (4 режима), датчик дневного света (3 режима) | ✅ |
| Прочее | Факел и фонарь (гаснут под дождём), лестница-стремянка (3 вида) | ✅ |

## Структура

```
core/     Чистая Java 8 без Minecraft: правила атрибутов, формы, геометрия. Юнит-тесты.
          Этот код будет общим и для 1.16.5, и для 1.12.2.
common/   Код для 1.16.5, общий для Forge и Fabric (Architectury, Mojang mappings).
fabric/   Тонкая обёртка Fabric: регистрация, события, синхронизация.
forge/    Тонкая обёртка Forge: то же самое.
tools/    smoke-test.sh: запуск настоящего выделенного сервера с модом.
reference/ Исходники оригинала для сверки (не в git).
```

## Правила, которые не нарушаем

- **Сервер решает всё.** Клиент только предсказывает результат клика. Любое изменение мира
  на сервере проходит `Permissions.canModify`: дистанция, загруженный чанк, защита спавна,
  режим приключения и наблюдателя.
- **Без своих пакетов вида «сделай X в точке Y».** Клики идут через ванильные события
  использования и удара по блоку, поэтому их видят приваты и защита спавна.
  Единственное исключение — удар молотком на Fabric. Его пакет проходит те же проверки
  и выполняется в основном потоке сервера.
- **Клиентский код только в клиентских точках входа.** Это проверяется запуском
  настоящего сервера, а не dev-окружения, где клиентские классы всегда доступны.
- **Ничего не пропадает.** Содержимое блока выпадает при любом удалении: игроком,
  взрывом, `/setblock`. У каждого блока есть таблица дропа.
- **Формат сохранения версионирован** (`cbVersion`). Идентификаторы атрибутов
  (`cover.host`, `dye.north`, …) не меняются.

## Сборка и проверка

Нужны JDK 17 (для Gradle) и JDK 8 (для запуска серверов 1.16.5).

```bash
./gradlew build                 # сборка + юнит-тесты core
tools/smoke-test.sh fabric      # настоящий сервер Fabric + автопроверки
tools/smoke-test.sh forge       # настоящий сервер Forge + автопроверки
tools/mp-test.sh fabric         # сетевая игра: настоящий сервер + два клиента по сети
tools/mp-test.sh forge
tools/client-test.sh fabric     # автоклиент: сцена, клики игрока, скриншоты, отчёт
tools/client-test.sh forge
./gradlew :fabric:runClient     # клиент для ручной проверки
./gradlew :forge:runClient
```

Готовые jar-файлы: `fabric/build/libs/carpentersblocks-<версия>+mc1.16.5-fabric.jar` и
`forge/build/libs/carpentersblocks-<версия>+mc1.16.5-forge.jar`.

### Настройка на сервере (датапак)

Отдельного конфиг-файла нет: всё настраивается обычным датапаком, без перезапуска (`/reload`).

- **Рецепты и количество:** положить свой файл с тем же именем в
  `data/carpentersblocks/recipes/` (например, `stairs.json` с другим `count`).
- **Выключить блок:** заменить его рецепт пустым рецептом или удалить через датапак.
  Уже поставленные блоки продолжат работать.
- **Что считается покрытием, подсветкой:** теги `data/carpentersblocks/tags/items/`
  (`cover_whitelist`, `cover_blacklist`, `illuminators`).
- **Дроп:** таблицы `data/carpentersblocks/loot_tables/blocks/`.

### Сетевой тест

`tools/mp-test.sh <платформа>` поднимает настоящий выделенный сервер с собранным jar.
Тестер A заходит по сети и настоящими кликами вешает покрытие, бьёт молотком, открывает
дверь, включает рычаг и ставит склон. Тестер B заходит после него и должен увидеть всё
это в загруженном мире. Нужен один предварительный запуск `tools/smoke-test.sh`, который
устанавливает сервер.

### Автоматический клиент

`tools/client-test.sh <платформа>` запускает dev-клиент с `-Dcarpentersblocks.clientTest=true`.
Сценарий `ClientScenario` делает следующее:
- создаёт мир и строит сцену с экспонатами;
- кликает через настоящий путь ввода игрока (`gameMode.useItemOn` / `startDestroyBlock`);
- проверяет результат на сервере;
- снимает скриншоты днём и ночью и закрывает игру.

Результаты лежат в `<платформа>/run-clienttest/`: отчёт `cbtest-report.txt` и
скриншоты `screenshots/cbtest-*.png`. Во время прогона окно игры трогать нельзя.
Новые проверки и ракурсы добавляются в `ClientScenario`.

## Управление (как в 1.7.10)

| Действие | Результат |
|---|---|
| ПКМ блоком | основное покрытие; если оно уже есть — покрытие на сторону |
| Shift + ПКМ красителем / светопылью | краска / подсветка |
| ЛКМ или ПКМ молотком | плотницкий блок: полный блок ↔ плита |
| Shift + ЛКМ молотком | снять атрибут: подсветка → оверлей → краска → покрытие |
| ЛКМ / ПКМ молотком по склону | повернуть / следующая форма |
| Shift + колёсико со склоном в руке | сменить вид склона |
| Shift при установке склона или лестницы | не соединять с соседями |
| Молоток по лестнице | ЛКМ повернуть, ПКМ следующая форма |
| Молоток по складному блоку | ЛКМ опустить, ПКМ поднять ближайший угол (соседние подстраиваются) |
| Молоток по барьеру / калитке | ЛКМ столб (барьер), ПКМ стиль, Shift+ПКМ вариант обычного стиля |
| Молоток по двери / люку / гаражной двери | ЛКМ петля (дверь) или следующая опора (люк), ПКМ стиль, Shift+ПКМ «железный» режим |
| Молоток по кнопке, рычагу, плите, датчику | ЛКМ инверсия сигнала, ПКМ режим (плита: на кого, датчик: чувствительность) |
| Молоток по факелу / стремянке | сменить вид |
| ПКМ факелом по погасшему факелу | зажечь |

Что принимается покрытием, светом и оверлеем, задаётся тегами предметов в
`data/carpentersblocks/tags/items/`. Владелец сервера может переопределить их датапаком.
