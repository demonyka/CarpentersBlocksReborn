# Carpenter's Blocks (переписанный)

Новая реализация мода [Carpenter's Blocks](https://github.com/Mineshopper/carpentersblocks).
Поведение берём из версии 1.7.10, код пишем заново.

**Лицензия.** Код — Apache License 2.0 (`LICENSE`). Текстуры и логотип взяты из оригинального
мода и остаются под LGPL-2.1 (`LICENSE-ASSETS`), подробности в `NOTICE`.

**Авторство.** Идея, дизайн блоков, все текстуры и логотип — из оригинального мода
Carpenter's Blocks (© Mineshopper и участники, LGPL-2.1). Текстуры взяты без изменений,
три файла переименованы. Код этого репозитория написан заново.

Всё из 1.7.10, кроме **сейфа, кровати, цветочного горшка, плитки, датчика дневного света, стамески с узорами и оверлеев**.

## Совместимость

- **OptiFine (Forge), проверено с 1.16.5 HD U G7.** Блоки рисуются так же, как без него.
  Связные текстуры OptiFine работают на покрытиях: стекло, цветное стекло, книжные полки,
  песчаник и правила из ресурспаков. Плотницкие блоки соединяются между собой и с
  настоящими блоками в обе стороны: стена из стекла и блоков со стеклянным покрытием
  выглядит одним полотном. У OptiFine нет API, поэтому мод вызывает его внутренние методы.
  С другой сборкой OptiFine связность может отключиться (в логе будет предупреждение),
  сами блоки при этом рисуются как обычно.
- **Chisel / CTM (Forge), проверено с Chisel 2.0.1-alpha.4 и CTM 1.1.2.6.** Покрытие из
  блока со связной текстурой соединяется с соседними покрытиями и с настоящими блоками
  Chisel в обе стороны. Плотницкие блоки объявляют себя «фасадами» через API мода CTM.
- **Jade / HWYLA (Forge), проверено с Jade 2.8.3.** В подсказке плотницкого блока есть
  строка «Покрытие: …» с блоком, который в него вставлен.
- **Прозрачные покрытия.** Цветное стекло, лёд, слизь и мёд рисуются полупрозрачными.
  Между двумя одинаковыми стеклянными покрытиями внутренние грани скрываются, как у
  настоящего стекла.
- **Fabric + Sodium:** нужен **Indium** (для 1.16.5 — `indium-1.0.0+mc1.16.5`), как и для
  любого мода, рисующего блоки через Fabric Rendering API. Без Indium блоки рисуются своей
  формой, но без покрытий. Проверить: `GRADLE_ARGS=-PwithSodium tools/client-test.sh fabric`
  (с `-PnoIndium` — без Indium). В среде разработки mixin Indium к Sodium 0.2 не
  применяется из-за маппингов, поэтому полную связку надо проверять в обычном клиенте.
- **Приваты:** все клики идут через стандартные события использования/удара блока, их видят
  и отменяют моды приватов.

## Структура

```
core/     Чистая Java 8 без Minecraft: правила атрибутов, формы, геометрия. Юнит-тесты.
          Этот код будет общим и для 1.16.5, и для 1.12.2.
common/   Код для 1.16.5, общий для Forge и Fabric (Architectury, Mojang mappings).
fabric/   Тонкая обёртка Fabric: регистрация, события, синхронизация.
forge/    Тонкая обёртка Forge: то же самое.
tools/    Скрипты проверок: настоящий сервер (smoke-test.sh), сеть (mp-test.sh),
          автоклиент (client-test.sh), «боевой» клиент Forge для OptiFine и других
          модов, которые не запускаются в среде разработки (prod-client.mjs).
reference/ Исходники оригинала для сверки (не в git).
```

## Правила, которые не нарушаем

- **Сервер решает всё.** Клиент только предсказывает результат клика. Любое изменение мира
  на сервере проходит `Permissions.canModify`: дистанция, загруженный чанк, защита спавна,
  режим приключения и наблюдателя.
- **Приваты решают первыми.** Правый клик приходит в мод через обычный `Block#use`, уже
  после событий взаимодействия Forge и Fabric, где его отменяют моды приватов. Удар
  молотком на Forge слушается с низшим приоритетом и не для отменённых событий.
- **Свои пакеты — только два.** Удар молотком на Fabric (Fabric API не передаёт серверу
  отменённый на клиенте левый клик): сервер сначала спрашивает остальные моды через
  `AttackBlockCallback`, затем проходит те же проверки, что и обычный клик. И смена
  вида склона колёсиком, которая меняет только предмет в руке игрока.
- **Клиентский код только в клиентских точках входа.** Это проверяется запуском
  настоящего сервера, а не dev-окружения, где клиентские классы всегда доступны.
- **Ничего не пропадает.** Содержимое блока выпадает при любом удалении: игроком,
  взрывом, `/setblock`. У каждого блока есть таблица дропа.
- **Формат сохранения версионирован** (`cbVersion`). Идентификаторы атрибутов
  (`cover.host`, `dye.north`, …) не меняются.

## Сборка и проверка

Нужны JDK 17 (для Gradle) и JDK 8 (для запуска серверов 1.16.5).

Собираются два вида jar. Обычный — для игроков, без тестового кода. С `-PwithTests` —
с автотестами внутри (суффикс `-tests`), его запускают скрипты проверок. В обычном jar
тестовые флаги JVM ничего не включают.

```bash
./gradlew build                 # jar для выпуска + юнит-тесты core
./gradlew build -PwithTests     # jar с автотестами для скриптов ниже
tools/smoke-test.sh fabric      # настоящий сервер Fabric + автопроверки
tools/smoke-test.sh forge       # настоящий сервер Forge + автопроверки
tools/smoke-test.sh forge release   # jar для выпуска запускается на настоящем сервере
tools/mp-test.sh fabric         # сетевая игра: настоящий сервер + два клиента по сети
tools/mp-test.sh forge
tools/client-test.sh fabric     # автоклиент: сцена, клики игрока, скриншоты, отчёт
tools/client-test.sh forge
./gradlew :fabric:runClient     # клиент для ручной проверки
./gradlew :forge:runClient
```

Готовые jar-файлы: `fabric/build/libs/carpentersblocks-<версия>+mc1.16.5-fabric.jar` и
`forge/build/libs/carpentersblocks-<версия>+mc1.16.5-forge.jar`.

### Настройка на сервере (датапак)

Отдельного конфиг-файла нет: всё настраивается обычным датапаком, без перезапуска (`/reload`).

- **Рецепты и количество:** положить свой файл с тем же именем в
  `data/carpentersblocks/recipes/` (например, `stairs.json` с другим `count`).
- **Выключить блок:** заменить его рецепт пустым рецептом или удалить через датапак.
  Уже поставленные блоки продолжат работать.
- **Что считается покрытием, подсветкой:** теги `data/carpentersblocks/tags/items/`
  (`cover_whitelist`, `cover_blacklist`, `illuminators`).
- **Дроп:** таблицы `data/carpentersblocks/loot_tables/blocks/`.

### Проверка с OptiFine и Chisel

Эти моды не работают в среде разработки, поэтому их проверяют в «боевом» клиенте Forge:
`tools/prod-client.mjs` сам ставит Forge-клиент в `run-dedicated/client-forge` и запускает
игру с модами из указанной папки.

```bash
mkdir -p run-dedicated/of-test/mods
cp forge/build/libs/carpentersblocks-*-forge-tests.jar run-dedicated/of-test/mods/
cp путь/к/OptiFine_1.16.5_HD_U_G7.jar run-dedicated/of-test/mods/     # и/или Chisel + CTM
node tools/prod-client.mjs run-dedicated/of-test --jvm "-Dcarpentersblocks.clientTest=true"
```

Сцена со связными текстурами снимается в `screenshots/cbtest-connected_*.png`. Блоки других
модов добавляются в неё флагом `-Dcarpentersblocks.ctmBlocks=chisel:factory/circuit,...`.

### Сетевой тест

`tools/mp-test.sh <платформа>` поднимает настоящий выделенный сервер с собранным jar.
Тестер A заходит по сети и настоящими кликами вешает покрытие, бьёт молотком, открывает
дверь, включает рычаг и ставит склон. Тестер B заходит после него и должен увидеть всё
это в загруженном мире. Нужен один предварительный запуск `tools/smoke-test.sh`, который
устанавливает сервер.

### Автоматический клиент

`tools/client-test.sh <платформа>` запускает dev-клиент с `-Dcarpentersblocks.clientTest=true`.
Сценарий `ClientScenario` делает следующее:
- создаёт мир и строит сцену с экспонатами;
- кликает через настоящий путь ввода игрока (`gameMode.useItemOn` / `startDestroyBlock`);
- проверяет результат на сервере;
- снимает скриншоты днём и ночью и закрывает игру.

Результаты лежат в `<платформа>/run-clienttest/`: отчёт `cbtest-report.txt` и
скриншоты `screenshots/cbtest-*.png`. Во время прогона окно игры трогать нельзя.
Новые проверки и ракурсы добавляются в `ClientScenario`.

## Управление (как в 1.7.10)

| Действие | Результат |
|---|---|
| ПКМ блоком | покрытие, если его ещё нет; иначе блок ставится рядом как обычно |
| Shift + ПКМ блоком по покрытому блоку | покрытие на сторону (блок, склон, лестница; другой блок, чем основной) |
| Shift + ПКМ красителем / светопылью | краска / подсветка |
| ЛКМ или ПКМ молотком | плотницкий блок: полный блок ↔ плита |
| Shift + ЛКМ молотком | снять атрибут: подсветка → краска → покрытие |
| ЛКМ / ПКМ молотком по склону | повернуть / следующая форма |
| Shift + колёсико со склоном в руке | сменить вид склона (в креативе лежит один склон, остальные виды — колёсиком или крафтом) |
| Shift при установке склона или лестницы | не соединять с соседями |
| Молоток по лестнице | ЛКМ повернуть, ПКМ следующая форма |
| Молоток по складному блоку | ЛКМ опустить, ПКМ поднять ближайший угол (соседние подстраиваются) |
| Молоток по барьеру / калитке | ЛКМ убрать или вернуть столб (барьер), ПКМ стиль, Shift+ПКМ вариант обычного стиля |
| Молоток по двери / люку / гаражной двери | ЛКМ петля (дверь) или следующая опора (люк), ПКМ стиль, Shift+ПКМ «железный» режим |
| Молоток по кнопке, рычагу, плите | ЛКМ инверсия сигнала, ПКМ режим плиты (на кого срабатывает) |
| Молоток по факелу / стремянке | сменить вид |
| ПКМ факелом по погасшему факелу | зажечь |

Что принимается покрытием и подсветкой, задаётся тегами предметов в
`data/carpentersblocks/tags/items/`. Владелец сервера может переопределить их датапаком.
